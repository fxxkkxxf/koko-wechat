# 可可微信助手 0.7.4

0.7.4修正微信重启后的重连：显式绑定会重新核对当前进程打开的账号文件，数据库与图片参数不再复用旧进程实例。「重新连接并继续接收」现在会暂停、重新绑定同一账号、只读验证实际聊天控件，再按原开关恢复监听；失败或用户手动暂停时不自动开启。只接收重连后的新消息，不补发旧回复。详见[0.7.4窗口重连修复](docs/0.7.4-窗口重连修复.md)。

0.7.3补上无障碍接口失联时的受控重建：普通唤醒后仍无可用控件时，对已绑定进程中桥接库识别出的无障碍运行标志逐项重建；实际读到输入框或会话列表才算成功，失败恢复原值。当前页面只有会话列表时允许打开唯一匹配目标，不再把所有“没有输入框”都当成接口故障。“检测连接”现在检查实际桥接进程内的聊天控件。详见[0.7.3控件恢复检修](docs/0.7.3-控件恢复检修.md)。

0.7.2修正后台短句的接管误判：仅本轮实际在微信内点击、滚动或键入时停止，鼠标移动、查看窗口或程序引起的前台变化不算人工接管。短句仍整批共用一次窗口准备；输入前等空框稳定并等待Qt焦点就绪，回读最长等待2.5秒，回读失败显示字符数量诊断。详见[0.7.2短句中断修复](docs/0.7.2-短句中断与输入核对.md)。

0.7.1把会话开关与故障状态分开：控件休眠会尝试唤醒；临时故障只暂避15秒起、连续失败最长5分钟，再处理后续新来信，不改群开关或自动回复总开关。真正发送不明只挂起对应会话并显示待核对，不重发旧消息。管理页显示原因与等待时间。详见[0.7.1稳定性修复](docs/0.7.1-临时故障恢复.md)。

一个在本机运行的微信聊天助手：微信桥接负责接收文字、读取收到的图片和发送文字回复，Codex负责理解、人设与回复。白紫管理页提供账号绑定、开启/暂停、独立本地试聊、人设编辑、记忆和原消息与回复对应的运行记录。

双击「打开可可微信助手.cmd」启动本机管理页；「创建桌面快捷方式.ps1」可建立独立桌面入口。电脑需要安装Node.js 22+、已登录的Codex CLI，以及桥接所需的Python依赖。其他电脑可用Python 3.12运行`python setup.py`建立独立环境；首次安装需联网。不会自动安装开机启动。

## 使用

1. 在电脑微信中正常登录自己的小号，保持图形桌面可交互。
2. 管理页检测连接，首次绑定自己的小号；在「参与会话」点击加载通讯录，搜索、筛选并勾选群聊和联系人，点击「应用选择」。加载目录只读取元信息，不会自动全选，也不读取未参与会话的消息。
3. 用「本地试聊」测试Codex回复；这个区域不会发送微信消息。
4. 开启自动回复后，只处理绑定会话此后收到的新文字和图片消息。暂停后不再开始新的回复；已经提交的发送无法撤回。

## 指定群聊

「参与会话」统一管理群和私聊，可按当前筛选结果一键勾选或取消，再一次应用。上限同时20个私聊、10个群；取消全部会话会暂停回复。旧绑定信息仍作为账号元信息保留，实际回复范围以勾选名单为准。原群聊折叠面板继续提供每群详细接话规则。不会自动加入新群或给未选择的会话回复。

可选三种触发方式：仅被@时回复；被@、明确叫到名字或同一位群友接着聊时回复；由模型自主判断是否接话。默认采用第二种，群回复间隔8秒、同一成员接话窗口90秒。群友改为@别人时不会继续把它当作和可可聊天。

群成员按真实发送者区分，群与私聊的历史、记忆分开；群聊使用独立的公开角色设定，不自动把私聊人设里可能写入的主人信息带进群。可在「群聊里的可可」中编辑群用语气。群内发送普通文字，不伪造真正的成员@或@所有人。

## 消息节奏

日常聊天以每条约6～7字为大致节奏，通常1～3条、最多4条；不按字数机械切词。解释原因、给步骤或详细讨论时允许完整的长消息，代码、列表、网址保留结构。角色设定中的「微信消息节奏」一节说明规则，原人设保留。

模型用换行标明独立气泡，短句整批打开一次目标聊天，默认气泡间额外间隔250毫秒。默认采用后台文字通道：使用UIA事件监听取得控件树，通过窗口消息输入、点击发送，不抢前台、不开剪贴板，不自动回退前台。前台兼容模式仍保留，选择后整批激活一次、发送后恢复一次。单条和本地试聊均兼容。每一条都独立核验；暂停、用户操作微信、会话变化或发送不明确时停止剩余，不盲目重发。已确认的部分才进入已说出的会话历史。私聊收到新消息时会停止旧回复的后续短句。

管理页「微信文字怎么发」可切换后台或前台兼容，并选择自动、UTF-16或GBK编码。小号微信保持登录即可最小化：回复时临时还原到其他窗口后面，整批短句完成后重新最小化；并非全程保持最小化。目标应已存在于可读取的会话列表，找不到时先在微信打开一次。自动编码检测只在核对过的空输入框里临时输入一个字符、回读后清空，不按发送；完整正文必须回读一致，否则停止发送。为避免ValuePattern激活微信，后台模式改用窗口消息清理自有草稿；多行或制表文字需要手动选前台兼容。详情及本机验收边界见[0.6.1最小化兼容说明](docs/0.6.1-最小化后台回复.md)。

## 群聊主动搭话

在「群聊与主动搭话」中，找到已接入的群，点击「开启主动搭话」。该群仍受群开关和自动回复总开关控制。只在本群有新消息时，结合最近的群内聊天判断是否适合加入，可以选择旁听。新选的群默认仍为点名接话，升级保留已有选择。

默认主动搭话至少间隔120秒，每个群每滚动一小时最多3轮，整轮的多条短句计一次；点击该群「编辑」可调整。被 @、叫名字和接续对话使用原来的普通回复规则。模型判断至少间隔20秒，纯表情和简短附和先旁听；主动判断会增加模型用量。关闭后恢复该群原来的点名规则。后台最近活动会显示原消息、主动判断与实际回复。详见[0.7.0主动搭话说明](docs/0.7.0-群聊主动搭话.md)。

## 识图与运行记录

收到的图片经当前账号、聊天、消息分片和消息编号核对后，从微信本地缓存读取原图、压缩图或缩略图，使用模型原生图片输入；微信常见的WXGF/HEVC完整图会先通过本地解码组件转成JPEG。不会把图片字节或本地路径拼进提示词、公开搜索或聊天历史。每次最多4张、单张10MB；图片需通过实际解码和尺寸校验。群聊仍遵守接话规则，同一成员先发图再提问时最多暂存30秒；不会拿其他成员的图片当作提问者的图片。

图片事件先于附件或元数据落盘时，会在最多约2秒的短窗口内尝试读取当前这条附件，暂停或监听器变化会及时取消。首次图片参数提取失败不会永久锁死，冷却后可重试；参数按实际账号和微信进程隔离。WXGF转换限制单帧、24MP、10MB和8秒，失败可退回同一消息的可用缩略图，不自行下载新软件或打开微信图片窗口。

图片未下载、解码失败、只有低清缩略图或文件已过期时，会告知限制，不凭文件名猜图。微信复用较早月份的图片缓存时可能无法读取；可打开原图后重发。模型需要支持图片输入，后续线程轮换只重注入有限文字上下文，不永久保存所有图片语义。

管理页显示正在处理的原消息、发言人、会话及准备发送的回复，历史记录按原消息ID配对，不按时间邻近猜对应关系。图片另外显示“已读取几张、原图/压缩图/缩略图、未读到的具体原因、提交模型中/模型已返回/模型未接受图片”；单有“[图片]”占位不算读取成功，也不把模型返回等同于识别准确。逐条区分已确认、未确认、未发送；旧记录缺少关联信息时明确标注。发送不明的记录先尝试只读核对，无法核对时可在人工检查微信后选择“已核对，跳过旧消息”，保留原未知状态，后续不会重发这条旧回复。

模型可在首屏下拉框自由切换，只列出该账号实际可用的选项。首次默认优先可用的Luna系列和最低受支持思考档；切换后自动回复暂停，用户重新开启生效，选择会保存在本机，重新打开不会重置。切换只影响可可微信助手，不改变Codex全局模型。

连接和模型响应是两段不同的等待。本机最初发现WebSocket多次失败重试会令冷首轮接近两分钟，因此本应用使用Codex官方支持的HTTP/SSE传输。本次Luna冷会话短自检约6.6秒、重试0次；这是一条短消息的实测，不保证所有消息同速。页面保存实际耗时，不以“连接成功”表示回复已生成。

请区分微信桥接进程已启动、微信账号可用、Codex已登录及实际消息已发送。界面显示实际连接状态，失败不会伪装成功。文字发送结果不明会暂停，避免重复发送。锁屏、睡眠、掉线、界面升级都可能中断运行；需要恢复图形桌面后重新检测。

## 数据与模型

人设素材在assets，首次运行复制到本机设置。会话、记忆、绑定、去重和运行记录保存在本机数据目录，默认用户目录的`.koko-wechat`，也可用`KOKO_WECHAT_HOME`或`runtime.local.json`指定。数据是本地明文文件，不适合公开上传。发布时排除runtime.local.json、data、venv、日志和个人数据库。

模型调用复用本机Codex CLI的登录。使用ChatGPT登录时消耗该账号可用的Codex额度；API登录则遵循API账户计费。它不会自动继承ChatGPT里的聊天记录，也不包含语音转写服务。微信来信是对话内容，不能授权模型运行电脑命令或自行更换收件人。

当前版本支持最多20个指定私聊与10个指定群的文字回复和图片理解。本地试聊、私聊和群聊分别维护上下文；B站任务没有与微信混用或自动导入其他联系人信息。

## 记忆和上下文

参考 AstrBot、SillyTavern、Mem0 的公开实现，采用「最近原话＋滚动摘要＋独立事实记忆」。最多12条近期消息、8000字符；累计24条或12000字符后，在已确认回复后后台整理较旧内容，默认至少间隔5分钟。摘要最多2400字符；失败时明确显示为本地摘录，原文近期归档仍保留。原文归档仍为每会话200条、全局2000条，非永久全量数据库。

长期事实按账号、会话和群成员隔离，按字词相关度召回；每次最多8条、1800字符，没有引入付费embedding或向量数据库。可按条忘记，或按会话清空事实与摘要；删除会使相应旧工作上下文失效，避免从摘要里马上记回来。管理页能查看摘要和整理次数。摘要可能省略细节，不能保证逐字记住。

模型端线程也会按摘要版本、12轮或约36000字符轮换，重新注入有限的工作上下文，而非仅截短页面上的记录。具体设计与来源见[记忆与上下文调研](docs/记忆与上下文调研.md)。

## 联网查资料

在管理页开启「联网查资料」。聊天模型先结合当前话题理解公开问题，提取游戏、产品、地区等主体和关键词；稳定常识正常回答，需要核实的公共事实交给独立的公开资料研究流程。研究流程可以自行换关键词、搜索、打开公开网页正文、核对来源；最多4次网络行动、整体90秒上限，防止无限循环。搜索摘要与已读正文分别标明，实际失败后可以换词或换来源，信息不足则说明具体未核实的部分。

当前Codex接入的实际探测没有观察到原生web_search调用，所以生产使用结构化计划协议：模型返回下一步计划，由应用真正执行HTTP搜索与网页读取，再把结果交回模型。它不依赖模型口头声称“查到了”，也不宣称已经获得ChatGPT聊天栏全部搜索能力。公开研究客户端不接收微信历史、人设、摘要、图片或长期记忆，仅接收提炼的公开问题与本轮公开资料；查询会去除或拒绝可识别的手机号、邮箱、账号ID和凭证片段，但仍应避免主动在公共查询中写入私人内容。结果附实际来源网址，不作为个人事实存入长期记忆。

天气使用独立的Open-Meteo地理编码和预报HTTP通道，不从搜索摘要拼温度。核对城市、日期、温度单位和数据时间；地点缺失或重名时先询问，不推断用户所在地。当前天气标注为模型估计，预报不是气象站实测。补城市、问“那明天呢”只沿用同一账号、同一会话、同一群成员的短期上下文。清空状态或关闭联网后，旧请求迟到的成功和错误都不能写回旧地理上下文。

只有实际网络请求取得有效来源才标记成功。未取得来源会明确提示，不会把模型声称「查到了」当作联网验证。管理页显示本次查询词、规划/搜索/读取正文进度、来源类型和具体错误；新查询失败不会显示上一条成功结果。管理页「试查」只在本地展示、不发微信。研究和聊天均使用已保存的模型与思考档，短查询有5分钟缓存。多轮核实比直接回答耗时更长，验收中一次官网查询约54秒；受模型、网站与网络影响，不承诺固定速度。公开搜索可能限流、摘要过旧；登录门禁、反爬和纯JS网页可能读不到正文，天气服务也可能连接失败，不保证所有问题都有结果。首次安装默认关闭，由使用者自行开启。具体证据和限制见[0.5.0联网研究修复说明](docs/0.5.0-联网研究修复说明.md)。

微信接入参考了[whale_gril v3.60](https://github.com/Banan1cee/whale_gril/releases/tag/v3.60)的后台监听、发送时操作界面和恢复窗口的工作流。具体桥接实现和依赖见bridge目录。参考项目支持不等于所有微信版本均已验证。

微信个人号的第三方自动化受到平台协议限制，使用可用性和账号状态取决于微信规则及实际客户端。
