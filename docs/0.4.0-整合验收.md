# 0.4.0 整合验收记录

日期：2026-10-31（Asia/Shanghai）。本次只修改源码和进行隔离测试，没有发送真实微信消息，没有重启、停止或修改生产服务配置。

## 已完成

1. **整批短句单次操作窗口。** 一组消息共用一次前台会话，打开目标聊天一次，发送完后恢复窗口一次；默认气泡间额外间隔250毫秒。每条独立核对，失败、取消、人工接管时停止后续，不盲目补发。修复了持久记录写入后、按Enter前的取消和草稿变化竞态。
2. **联网先取得资料再组织回答。** 普通问题支持模型提出具体公开查询关键词，由应用实际HTTP检索；天气走独立地理编码和预报接口，校验城市、日期、单位和数据时间。缺城市先问，不把搜索摘要当温度，不把网页事实存入个人记忆。查询失败提供具体状态，不假称查到。
3. **识图接入主流程。** 当前账号、聊天、分片和消息校验后读取图片，再以原生localImage提交模型。兼容微信库实际产生的message__message_N.db分片标签。群聊同一成员先图后问或先问后图可在短时间内合并；不同成员图片不混用。修复暂停、重开监听、切换账号期间迟到图片回调混入新会话的竞态。
4. **管理页原消息与回复对应。** 显示当前原消息、发送者、会话和准备发送的回复；历史按账号、会话、发言人和原消息ID关联。区分各气泡已确认、未知和未发送，长文本可展开，旧记录缺少关联时不猜配对。本地路径不显示在错误标题中。
5. **天气竞态回归修复。** 请求记录启动时的代次，clear后迟到的AMBIGUOUS_CITY或CITY_NOT_FOUND错误不再写回地理上下文、lastResult或运行状态；排队中的旧查询也不能在重新开启后复活。补城市保留原日期，新的完整天气问题恢复当天默认值。

## 尚未执行与实际限制

- **尚未部署或做真实微信收发联调。** 这是本轮明确限制；不能把隔离测试通过等同于生产收发已验证。后续正式切换需另行安排。
- 微信窗口自动化仍依赖桌面解锁、客户端可用、目标窗口可核对；客户端升级或手动切窗可能中止发送。发送不确定时保留记录，不自动重试。
- 图片需已在当前账号的本地缓存中。微信复用更早月份缓存、未下载原图或特殊格式时可能无法读取；只提示失败，不猜图。最多4张、每张10MB，并受图片解码尺寸限制；模型本身需支持图片输入。
- 外部搜索和天气服务可能超时、限流或覆盖不足。天气是模型估计与预报，不是气象站实测；一般搜索结果也可能包含旧摘要。
- 旧历史若没有保留消息关联或发送基线，无法无损恢复。管理页保留“未关联”或“待核对”，不会补造事实。
