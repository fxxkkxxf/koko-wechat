# 0.7.2 短句中断与输入核对

近期记录显示同一批回复第一条已确认，第二条被USER_TAKEOVER阻止。旧版用全局最后输入时间和微信是否前台判断接管，鼠标移动也会改变这个时间；程序自身引起的窗口变化也可能被误认为用户切回微信。因此即使本轮没有真实编辑，也可能停止后半段。

## 调整

- 发送会话期间使用独立消息线程观察输入事件。仅与已绑定微信窗口及其子窗口关联的点击、滚动和非修饰键按下才标记接管；鼠标移动、其他应用中的操作不标记。窗口前台变化本身不再作为接管依据。
- 观察只保留一个「本轮发生过实际操作」布尔值；不记录按键内容、不保存输入轨迹、不消费或拦截用户输入。会话结束或准备失败后卸载观察。观察不可用时停止本轮，仍保留草稿和发送核对保护。
- 同一批短句继续共用一次窗口准备和观察生命周期。程序引起的窗口变化不会单独取消第二、第三条；用户真的在微信操作时仍停止后续条目。
- 每条开始前确认空输入框稳定；后台发出焦点消息后等待100毫秒让Qt完成焦点切换，字符间隔调整为5毫秒。完整文字回读等待从1.6秒延长至2.5秒，仍须连续两次完整一致才允许发送。
- 不通过忽略回读错误来继续发送。诊断只保存计划和实际回读的字符数量，不复制额外的聊天正文。管理页会显示这些数量，区分读不到输入框和漏字等情况。
- 不补发历史失败的后半段，不重发已经确认的前半段；本机发送记录确认和未知发送的待核对状态继续保留。

## 验证边界

2026-11-08在自动回复暂停、脚本禁用全部点击的条件下，连续输入三条自检短句，包括中文、英文和数字；均完整回读并清空自检草稿，前台保持不变，未发送真实微信消息。输入观察已在本机成功建立和卸载。

模拟回归覆盖程序切前台后继续三条短句、鼠标移动不误判、真实点击/滚动/键入停止、观察失效、清理生命周期和输入途中出现人工草稿。草稿验证不能代替真实发送送达验收；输入等待是稳定性改进，尚未证明所有回读不一致均已解决。
