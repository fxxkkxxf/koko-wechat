# 0.6.0 后台文字发送

## 使用

管理页「微信文字怎么发」默认选后台发送。小号微信需要保持登录，打开主窗口并保持未最小化，可以用其他窗口盖住它。首次建议在微信中打开一次目标聊天，让其出现在会话列表。随后正常使用其他应用，助手不主动切到前台。

后台模式失败会显示具体原因并停止相应回复，不自动切前台。需要旧方式时手动选择「前台兼容 · 发完恢复」。原有账号、参与会话、模型、人设、记忆和未知发送记录均沿用。升级不擅自开启原先已暂停的自动回复。

## 实现

- 标准UIA事件订阅保持提供者可用，以绑定的HWND和进程读取控件，避免把窗口外壳当成完整可用的控件树。必要时在本次会话期间设置屏幕阅读器标志，结束后恢复原值；后台模块不扫描或写入微信进程内存。
- 单行文本通过PostMessage传入WM_CHAR，依据精确回读检测UTF-16或GBK，发送前核验完整正文。GBK不支持的文字直接停止，不删除emoji或替换字符。
- 多行、制表文字由UIA ValuePattern写入，不将换行作为WM_CHAR或Enter发送，防止误触发送。控制字符被拒绝。
- 只在同一绑定窗口的唯一匹配会话上操作。当前聊天或目标有草稿、不可读、同名不唯一时不修改。仅按完整名称匹配，不把群A和群A2混同。
- 不调用真实键盘输入、剪贴板或前台激活，不自动显示隐藏/最小化窗口。不采用OCR坐标兜底。
- 每条都在点击发送之前持久化账本，点击后继续核对本地新增本人发送记录。输入框清空不作为送达证明，结果未知不重发。
- 短句整批共享一次会话准备，每条独立确认。用户在其他应用工作可继续；用户转到微信操作、会话改变、暂停或取消时停止后续。
- 既有前台兼容路径保留，必须明确选择才使用；和后台路径没有自动失败重试关系。

## 本机验证与边界

2026-11-05在绑定的小号正常聊天界面验证：标准UIA读取172个控件，进程与窗口绑定一致；读取9条可见会话，其中6条属于当时所选范围。数量仅代表当次窗口可见情况，不是支持数量上限。

在自动回复暂停状态下进行临时输入框自检：自动识别UTF-16，中文、英文、数字与标点完整回读；定位到启用的发送按钮；自检草稿精确清空，前台窗口不变。自检程序禁止点击任何按钮或按Enter，真实微信消息发送数为0。

完整发送和确认、相同短句、取消、草稿变化、账号切换、窗口接管和失败隔离使用模拟回归验证。未进行真实消息的发送验收，因此上述输入自检不是“真实消息已送达”的证明。后续使用中仍以实际本机发送记录核对。

发布回归：Node 243项通过；Python 128项（127通过、1项Windows符号链接相关跳过）；管理页140项检查通过，未发现JS错误。活动记录页在多浏览器并行时曾遇到固定等待过短，单独复核36项通过；未为此更改业务逻辑。

最小化/托盘、控件树不可读、未出现在可见会话列表、微信权限/版本变化等可能使后台发送停止；可先打开目标会话，或手动切换前台兼容。此版本不新增表情包或语音功能。

## 参考

窗口消息后台思路参考[whale_gril的后台发送实现](https://github.com/Banan1cee/whale_gril/blob/1eede8b069581097cb6256631335b8a6bf1b2725/bridge/bg_sender.py)。本版独立实现，继续使用可可原有的账号核验、批次与持久账本，没有运行上游服务或沿用其“输入框清空即视为成功”的判定。

UIA监听依据[Microsoft UI Automation事件订阅文档](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-eventsforclients)，屏幕阅读器标志依据[SystemParametersInfoW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow)。
