# 0.6.1 最小化后台回复

## 使用方式

管理页选择「后台发送」，小号微信保持登录，可以最小化。收到需要回复的消息时，助手把已绑定的主窗口临时还原到其他应用后面，不主动激活它；整批短句结束后重新最小化。隐藏到托盘的窗口也采用临时显示、完成后隐藏的路径，但本机实测覆盖的是最小化路径，托盘仍需使用验证。

这不是全程保持最小化的发送。发送期间若用户打开、移动微信或切换账号，助手停止相关操作，不强行把用户正在用的窗口最小化。微信置顶时先取消置顶；锁屏、微信退出、账号未登录不在支持范围内。电脑和助手服务仍需运行。

目标会话仍需出现在可读取的列表中。找不到时先手动打开一次聊天，再最小化。不会因为后台失败而自动切换到前台兼容模式。

## 本次修复

- 最小化后窗口客户区会缩小，UIA仍可能返回原位置的控件。本版先在后台临时还原并重新核验控件，再输入和点击，避免使用缩小窗口上的旧坐标。
- 短句整批共用一次后台还原，完成后只恢复一次窗口状态。
- 原有清空输入框的ValuePattern调用在本机有激活微信的情况。本版改用发往绑定窗口的Backspace消息，只清理完整回读匹配的自有草稿，逐次核验删除结果；内容改变就停止清理。
- 调整主窗口选择：同一微信进程可能同时存在隐藏登录窗口与主窗口。改按正常窗口面积选唯一主窗口，避免调整窗口层级后误选登录外壳；多个进程或大小无法唯一判断时拒绝猜测。
- 继续保留账号、会话、草稿、用户接管、发送前持久化与发送后数据库确认。不把输入框清空当成送达；未知发送不自动重发。

## 限制与验证

为避免ValuePattern激活窗口，多行、回车和制表文字暂不走后台输入，请手动选择前台兼容。部分emoji在当前微信的窗口消息通道中无法完整输入，正文回读不一致会阻止发送，可能需要手动检查残留草稿；不会悄悄删掉emoji继续发送。

2026-11-05在本机暂停自动回复后进行草稿自检：初始为最小化窗口，临时还原到其他应用后面，自动检测UTF-16编码，输入并完整回读中文、英文和数字，清理自检草稿后重新最小化。全过程前台应用保持不变。自检脚本禁用按钮点击，不按Enter，未发送真实微信消息。

实际消息发送及数据库确认使用模拟回归验证；草稿自检不等于真实发送送达验收。微信版本、权限或控件变化仍可能影响后台可用性。

发布回归：Node 243项通过；Python 135项（134通过、1项Windows符号链接相关跳过）；管理页发送模式14项通过，包含移动端溢出、保存失败与无意外启用等检查。

## 依据

后台还原采用[ShowWindow的SW_SHOWNOACTIVATE与SW_SHOWMINNOACTIVE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)；窗口层级调整采用[SetWindowPos的HWND_BOTTOM与SWP_NOACTIVATE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。本版不调用前台激活、全局键盘输入或剪贴板作为后台兜底。
