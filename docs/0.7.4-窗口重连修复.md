# 0.7.4 微信进程更换后的重连

## 问题

微信退出重登或启动新的进程后，即使仍是同一个账号，窗口句柄和进程也会变化。发送前的检查会拦住旧绑定；这个拦截继续保留。

旧版有两个恢复缺口：显式绑定可能直接复用账号目录中缓存的旧窗口；「修复后继续接收新消息」只清除会话的等待状态，没有真正更新绑定和监听。因此可以看到同一条错误反复出现。

## 调整

- 显式解析账号时，重新检查微信进程当前打开的数据库文件。仅选择仍能验证到的原账号，不改绑另一个登录账号。
- 数据库缓存按账号、进程、进程启动时间和数据库位置区分。同一进程切换窗口可保留缓存；更换进程后创建新的数据库适配器，避免沿用旧的图片参数等状态。
- 「重新连接并继续接收」先暂停并撤销旧任务，再绑定当前选择、只读检测实际聊天控件，通过后恢复原来的开启状态。重新监听使用新的消息基线，不补发旧回复。
- 重连失败时保留原来的问题记录并保持暂停。用户在重连中手动暂停或更改选择时，当前重连会停止。
- 同一账号的窗口问题可以一起解除；目标冲突、其他账号的问题和发送结果待核对的记录继续保留。

## 验证范围

回归覆盖缓存窗口过期、账号缺失、进程替换及 PID 复用、真实控件验证失败、手动暂停竞态、原开关保持暂停及旧消息不补发。现场只做账号核对与控件只读检测，不发送真实微信测试消息。
