# 0.4.1 识图修复

## 实际问题与证据

0.4.0运行中出现了“收到[图片]，但回复没读到图”的真实情况。旧版本只保存文字占位，未保留附件读取状态，导致控制台不能说明失败发生在哪一步。对用户本人发送的三条准确图片消息做只读复核后，发现两条完整图解密后为微信WXGF/HEVC容器；原先直接交给Pillow验证无法理解这种格式。

另外，首次图片参数获取失败会被永久记为“已检查”，以及收到消息时只尝试一次读取附件，均会使暂时故障持续表现为无法识图。这些路径已经加上恢复和回归验证。

## 修复内容

- 当前消息WXGF/HEVC完整图经本地FFmpeg转为JPEG，再按实际格式和像素限制验证。只解码一帧；限制24MP、10MB及8秒，失败只回退同一消息的缩略图。
- 兼容复合图片消息类型，仍精确核对账号、聊天、分片、消息编号和发送者。
- 明确可恢复的附件延迟最多等约2秒，检查暂停和监听器变化；永久错误或成功缩略图不重复解码。
- 图片参数首次获取失败可在10秒冷却后重试，微信进程更换时不复用旧参数。参数和密钥不进入控制台、模型提示或分发包。
- 原消息、当前任务、事件和对应回复都记录安全的图片状态，显示图片数量、质量档位、读取失败原因及模型提交/返回状态。
- 没有附件的占位明确标成未读到，不以[图片]文本冒充视觉输入；模型返回也不会直接标成识别准确。

## 验证范围

- 用本人此前失败的真实照片经读取器恢复出完整图，再走ChatController.generate和原生模型图片输入，模型正确描述蜘蛛侠商品货架、黄色托盘及红色横梁。
- 实图验证在独立目录进行，没有向微信群发送测试消息，也不重放失败的旧回复。
- 增加真实合成HEVC转码、复合消息类型、附件晚到、首次参数失败恢复、暂停取消与图片状态展示的回归检查。

旧记录缺少读取状态时仍显示未知，不会伪造旧图片曾经成功交给模型。尚未下载、历史月份缓存复用、外部模型不可用或极大图片仍可能失败，界面会给出具体状态。只读实图验证不能代替所有客户端和网络条件下的持续收发验证。
