# 0.7.1 临时故障恢复

## 为什么以前经常关闭

旧版把多种发送异常统一调用「暂停群聊」，直接写入群开关为关闭。单条发送在会话准备阶段抛出的错误没有保留「还未发送」的证据，管理端又只能保守当成发送中断。结果就是控件临时不可读、用户操作微信或输入框有草稿，也可能让群一直保持关闭。

本机还观察到微信长期运行后Qt无障碍接口休眠：标准订阅、读屏标志和普通重试只返回2个外壳节点。调用已安装的wechatauto无障碍唤醒接口后，恢复到183个节点，输入框可读。此接口针对已绑定窗口的微信进程唤醒运行时无障碍标志，不激活前台，不注入聊天内容；仍以实际读到的控件作为成功标准，不依赖库返回值。

## 新行为

- 会话开关和自动回复总开关保留用户选择。运行故障记录在独立、按账号和会话隔离的持久状态中。
- 控件读取失败先尝试唤醒和一次新的发送前控件连接；只在尚未输入、尚未发送的预检阶段重试，不重试发送动作。
- 明确未发送的故障进入暂避：15、30、60、120、240秒，连续失败上限300秒。到期后只由后续新来信重新验证；等待期间收到的消息保留记录，不自动补发旧回复。
- 草稿、用户接管等不再自动关闭群，依然不擅自删除人工输入或抢回窗口。账号或目标发生变化则显示等待修复，用户修复后可继续接收新消息。
- 已尝试发送却未确认、桥接通信中断或未知部分发送，仍挂起对应会话等待核对，其余会话继续运行。核对操作不会重发旧消息，也不会打开用户手动关掉的总开关或会话开关。
- 单条预检失败会返回持久化的blocked结果与错误码，不再退化成含糊的RPC异常。RPC原有错误码会保留，未知结果不按文案猜测成安全失败。
- 部分短句已确认、后续明确被阻止时，仅记录已确认部分并暂避；取消批次里若存在发送不明的部分，仍需核对。

## 管理页

群行内与「最近互动→会话运行状态」分别显示开关选择、故障原因、暂避倒计时或待核对状态。暂避到期显示等待新来信验证恢复；实际发送确认后清除故障状态。修复连接或核对发送后，可继续接收后续新消息，旧消息不会重发。

本次保持当前会话选择、模型、人设、记忆、主动搭话配置和发送账本。原有多行文字、特殊emoji和不同微信版本的兼容边界仍然存在；故障不再通过修改用户开关来表达。
